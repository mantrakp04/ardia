# Daily Briefs

Daily Briefs is an explicit exception to the deferred AI surfaces. It uses the selected provider to summarize only the sources allowed in Settings › Daily Briefs. Ordinary browsing, tabs, history and passwords are not context.

Open `ardia://brief/YYYY-MM-DD`, or use Open Brief in settings. Each date has its own tab and weekday artwork from the supplied images. The page displays generated brief content or the connection setup state.

Delivery is opt-in, defaults to 08:00 local time, and runs while Ardia is open. A missed time is caught up on the next launch with an eligible regular window. Delivery opens a background tab once per local day, so dismissing it does not reopen it. Transient generation failures retry separately, at most three automatic attempts per profile and local day, five minutes apart; that retry state survives relaunch. When I Open Ardia is also limited to one delivery per day. Private windows and Little Ardia are excluded. Past briefs are preserved; their content cannot be refreshed using today's source data.

ChatGPT uses the official open-source Sign in with ChatGPT dynamic registration flow. Ardia creates its own registration with secure PKCE, state and nonce, validates the returned identity signature and scopes, and keeps credentials in macOS Keychain. It does not import another app's access token. The user must approve ChatGPT plan usage. Available models come from the authenticated catalog; generation uses streaming Responses with storage disabled. A live sign-in and completed inference are needed to establish account eligibility.

Claude uses a personal Anthropic API key, verified before it is saved in Keychain. Its API usage is billed separately from a Claude subscription. API keys are never saved in settings or synced.

Calendar reads today's events from the accounts configured in macOS Calendar, including Google Calendar accounts. macOS permission and permission to share events with the selected provider are separate. GitHub uses the existing Live Folders connection, reading recent pull-request metadata and check status. Daily Briefs opens the GitHub account authorization flow first; Ardia uses its registered public OAuth app client ID with Device Flow enabled; users do not need to enter it. Connection credentials are saved in macOS Keychain; sharing GitHub content with a provider is a separate permission. Changing providers clears sharing consent. Revoking sharing prevents further submission; data already transmitted cannot be recalled.

Gmail uses Ardia's registered Google Desktop OAuth client and requests read-only Gmail access in the system browser. Authorization uses cryptographic state and S256 PKCE with a temporary loopback callback. The developer provisions this Google Desktop client’s matching credential using the `ARDIA_GOOGLE_OAUTH_CLIENT_SECRET` build setting, expanded into `ArdiaGoogleOAuthClientSecret` in the app’s Info.plist. Users never enter an OAuth client ID, client secret, or access token. Previously configured Keychain credentials remain supported. A build without app-level configuration or an existing local credential clearly shows Gmail sign-in as unavailable. Never commit the credential value; configure it in local build settings or CI. Tokens remain in macOS Keychain, separately from Drive. Connecting Gmail does not require a browser profile for the Google account and does not authorize sharing messages with a brief provider. The sharing permission is explicit and revocable in Daily Briefs settings. Briefs use a bounded selection of recent inbox metadata and snippets, without attachments. Google test users and applicable public OAuth verification remain configured in Google Cloud.

Briefs are saved separately from the browser session in the app data directory, partitioned by browser profile and date. The archive shows the most recent seven local calendar days, and the oldest day expires as a new day enters that window. Provider credentials, account login tokens and source credentials are excluded from the archive file. Sharing preferences and delivery markers remain local to the device.

The supplied reference has a 910 × 461 artwork at a page width of 1312 pixels, with side rails and two editorial columns. The page scales this geometry responsively and stacks the columns in narrower windows. Side labels are drawn by a native macOS view inside full-height vertical gutters, avoiding rotated React Native text clipping. Artwork credits accompany each image. Meeting rows use the calendar’s timestamps formatted in the Mac’s local timezone: a compact start time on the left and a readable time range on the right. Legacy saved ISO and dated UTC time strings are normalized when displayed.
