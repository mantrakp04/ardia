# 0.2.39 → 0.2.40 release gate

0.2.40 collects nightlies 1 to 9 and the window-drag fix for macOS 27: the Helium engine on Chromium 155, Peek, pinned folders and nested groups, Tidy, bangs, settings search, shared tabs and the other Arc options. 0.2.39 is native API 11 and 0.2.40 is 13, so the control ran its own bench bundle, built from `git archive v0.2.39` (`dist/0.2.39/bench/main.jsbundle`). The candidate is `dist/0.2.40/export/Ardia.app` (notarized, built from 657fcc07). Measured on 2026-10-24, interleaved, display awake.

The owner fast-tracked the release with the gate partly run, then had the rest run after it shipped, on mains power. With that, every row is the same as 0.2.39 within noise: no range separates. The rows that leaned worse in the first rounds were the Mac on battery.

## After the release, on mains

- **Idle**, `native-bench --only idle --runs 6`: 1 tab 1.70 % (1.21–1.75) → 1.72 % (1.28–1.83), 9.1 → 8.7 wakeups/s. 20 tabs lean up but overlap: 0.53 % (0.50–0.57) → 0.61 % (0.54–0.80), 14.1 (13.7–14.8) → 16.2 wakeups/s (14.3–21.1). Someone used the Mac 46–87 s of each run's idle windows.
- **Tab actions**, `tab-actions.mjs run --launches 4 --n 5`: pin and unpin, 2–4 ms slower on battery, are even (table below). Renders per pin and unpin are still up (188 → 266, 183 → 298): every pinned tile also renders its folder drop ring and face (a6475c68). Memoizing those two cut about 40 renders and no time.
- **js-bench**, three runs each, alternating: launch to first window 2600 → 2461 ms, typing max key 8.4 → 8.0, close 10.4 → 9.4, tab switch 11.4 → 11.7; close20 JS 90 → 94 ms with overlapping ranges.
- **profileSwipe** passed 9 of 9 later runs (6 alone, 3 in the round); the one failure in the battery round didn't come back.
- native-bench's session crash (an empty tab list before the switch phase) didn't come back in 3 later 0.2.40 sessions with the tab list logged.
