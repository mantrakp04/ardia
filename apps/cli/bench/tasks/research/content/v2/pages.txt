@@ overview
Halyard is a hosted event-streaming API. Publish events to streams over HTTPS and read them back with consumer groups or webhooks.

These pages document API v2. All v2 requests go to `https://api.halyard.dev/v2/`.

## Sections

- **Get started:** keys, your first stream and your first event.
- **Guides:** publishing, consuming and webhooks.
- **Platform:** plans, rate limits and other limits.
- **API reference:** every v2 endpoint.

@@ quickstart
## 1. Get an API key

Open **Settings › API keys** in the dashboard and create a key.

## 2. Create a stream

```bash
curl https://api.halyard.dev/v2/streams \
  -u "$HALYARD_API_KEY:" \
  -d name=orders -d partitions=4
```

## 3. Publish an event

```bash
curl https://api.halyard.dev/v2/streams/str_8Kq2vX/events \
  -u "$HALYARD_API_KEY:" \
  -H "Content-Type: application/json" \
  -d '{"type": "order.created", "data": {"total": 4200}}'
```

## 4. Read events

```bash
curl "https://api.halyard.dev/v2/streams/str_8Kq2vX/events?group=quickstart" \
  -u "$HALYARD_API_KEY:"
```

@@ authentication
v2 accepts the API key as the username in HTTP Basic auth, or as a bearer token.

```bash
curl https://api.halyard.dev/v2/streams -u "hk_live_51Hf2kQe8...:"
```

Keys have full access to the workspace. Scoped keys are only available in v3.

@@ concepts/streams
A stream is an ordered log of events split into partitions. Events with the same `key` go to the same partition. v2 streams support up to 64 partitions and 30 days of retention.

@@ concepts/consumer-groups
A consumer group is identified by name within a stream. Halyard stores one committed offset per partition for each group.

## Reading and committing

Read with `GET /v2/streams/{stream_id}/events?group=<name>`, then commit what you processed with [Commit consumer offsets](/v2/reference/commit-offsets). Check progress with [Get consumer offsets](/v2/reference/get-offsets).

> **Deprecated:** Both offsets endpoints are deprecated and have sunset dates. See each endpoint's page.

@@ guides/publishing
Publish one event per request with [Publish an event](/v2/reference/publish-event). v2 has no batch endpoint; use v3 for batching.

## Limits

Events can be up to 256 KB. Larger events fail with `413 event_too_large`.

@@ guides/consuming
Poll [Read events](/v2/reference/read-events) in a loop, process the events, then commit offsets. v2 does not support long polling, so sleep between empty reads.

```python
while True:
    events = client.read(stream, group="billing", max=200)
    if not events:
        time.sleep(1)
        continue
    process(events)
    client.commit(stream, group="billing", offsets=last_offsets(events))
```

@@ webhooks/overview
Webhooks deliver events to a URL you register with [Create a webhook](/v2/reference/create-webhook).

## Delivery

Halyard sends a `POST` per event. Respond with `200` within 15 seconds. Failed deliveries are retried 5 times over about 2 hours.

## Payload size

Webhook payloads are limited to **64 KB**. Events larger than that are not delivered by webhook.

@@ webhooks/signatures
v2 webhook requests include an `X-Halyard-Signature` header: an **HMAC-SHA1** of the raw request body, keyed with the webhook's secret, hex-encoded.

```python
import hmac, hashlib

def verify(body: bytes, header: str, secret: str) -> bool:
    expected = hmac.new(secret.encode(), body, hashlib.sha1).hexdigest()
    return hmac.compare_digest(expected, header)
```

v2 signatures don't include a timestamp, so they don't protect against replayed requests.

@@ platform/rate-limits
Requests are limited per workspace per minute.

| Plan | Requests per minute |
| --- | --- |
| Starter | 120 |
| Team | 600 |
| Business | 3,000 |
| Enterprise | Custom |

Requests over the limit get `429 Too Many Requests` with a `Retry-After` header.

Business and Enterprise workspaces can view an audit log of key, stream and member changes under **Settings › Audit log**.

| Plan | Retention |
| --- | --- |
| Business | 90 days |
| Enterprise | 180 days |

v2 has no audit log API. Use v3's [List audit events](/v3/reference/list-audit-events).

@@ reference/overview
All v2 requests go to `https://api.halyard.dev/v2/` and return JSON. Authenticate with your API key as described in [Authentication](/v2/authentication).

## Errors

v2 errors return a JSON body with a `message` field and an HTTP status code. Rate-limited requests get `429`.
